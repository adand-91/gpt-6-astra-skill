# Astra Skill Optimizer 1.0.3

Released on 2026-09-16. [中文](v1.0.3.zh-CN.md)

This release makes the existing Skill optimizer easier to install and more precise to use.
Jarvis remains the long-term personal project manager direction; this is a scoped maintenance
release, not a claim that an autonomous project manager is complete.

## Before and after

| Before | After | Evidence |
| --- | --- | --- |
| Catalog accepted only `description: >-`; valid inline, folded, or literal descriptions could be flagged missing. | Common scalar forms are recognized; uncertain syntax is marked for manual review. | `tests/test_audit_skill_catalog.py`; example below. |
| An explicit request to optimize could still trigger a second permission question. | The Skill preserves existing scoped edit authorization; publication still needs authority covering it. | Changed entry/authority instructions; model spot check described below. |
| Generic audit instructions included unrelated pricing and customer-message policies. | Project-specific rules stay with the selected project; the optimizer preserves capabilities without imposing those policies. | Skill, schema, case updates and distribution regression. |
| Installation led mainly to the legacy workflow and progress examples invented percentages. | English and Chinese quick starts expose both plugins; unknown progress has no invented percentage. | README pair, translation checker, plugin snapshots. |

## Reproduce the parser regression

```bash
python3 scripts/audit_skill_catalog.py examples/skill-audit
PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_audit_skill_catalog.py' -v
```

The example uses a normal inline `description`. The previous regex matched only the `>-` style;
its missing-description finding was a parser limitation, not a defective Skill. The corrected
checker reports static metadata findings and never certifies GPT-6 behavior. Its length threshold
and keyword checks are local review heuristics, not official OpenAI requirements. It is deliberately
not a complete YAML validator.

## Verification

Final local test counts and package/installation evidence are recorded in `HANDOFF.md` and the
GitHub release. The seven macOS skips do not establish Windows behavior; use the public CI run for
platform evidence. Scenario definitions alone are not model-run results. A separate task loading
the newly installed plugin is still required before claiming normal host auto-selection works.

A read-only independent agent spot check exercised three cases: an actual local audit, missing
project context, and continued scoped authorization (dry-run). It found a real multiline plain
scalar truncation in the parser; this was corrected to manual review and covered by a regression.
The other two cases requested target information without inventing a project and retained the
previous authorization. The evaluator's exact model identifier was unavailable, so this is not an
Astra-specific benchmark or host auto-selection test.

## Preserve and defer

Existing CLI commands, schemas, evidence binding, privacy checks, and domain Skill capabilities
remain compatible. The OpenAI-baseline/Astra two-pass contract is included. This release does not
train a model, edit external domain Skills, prove universal compatibility, or introduce unattended
project management. No private catalog, client records, or application identity is included.

Basis: [OpenAI's Astra Skill guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra),
reviewed 2026-09-16. Official advice guides the changes; it does not prove their runtime effect.
