# v0.2.0-alpha.1 — 可安装的点名目标审查

这是第一个公开 v0.2 预发布版。它把 Codex-first 审查契约变成一个小型、可安装、离线可用的
点名目标入口；范围有意小于完整 v0.2 规划。

[English](https://github.com/adand-91/requirement-ledger/blob/v0.2.0-alpha.1/docs/release-notes/v0.2.0-alpha.1.md) ·
[更新地图](https://github.com/adand-91/requirement-ledger/blob/v0.2.0-alpha.1/UPDATE_MAP.zh-CN.md) ·
[完整变更日志](https://github.com/adand-91/requirement-ledger/blob/v0.2.0-alpha.1/CHANGELOG.zh-CN.md)

## 更新了什么

- `requirement-ledger review-init --mode audit` 为一个显式目标和一个显式半开时间窗口创建私有
  审查骨架。
- `requirement-ledger review-check REPORT` 机械校验报告 Schema、时间窗口、时区、必需章节、
  证据标签、候选状态和授权声明。
- `scripts/check_review_report.py` 调用包内检查器，校验契约只保留一个实现。
- 审查骨架初始为 `analysis-only`、零已读取来源、覆盖不完整；平台支持时使用 `0600` 权限，且
  绝不覆盖已有文件。
- Windows 按平台条件安装 `tzdata`，让显式 IANA 时区校验在所有支持的操作系统上一致。
- 双语宿主契约、一次性／日报／周报参考模板、个性化工作流和十天更新地图让当前边界与后续门禁
  清晰可见。

## 解决了什么问题

| 之前 | Alpha 1 |
| --- | --- |
| 用户能点名 Skill 或项目，却没有可安装的目标专用审查入口。 | 一条命令生成目标与时间绑定、未知项明确的审查文档。 |
| Markdown 报告看着完整，却可能缺少必要证据或安全字段。 | 零依赖检查器会返回失败退出码和可执行的错误项。 |
| 独立脚本与安装包之间的校验逻辑可能漂移。 | 两个入口共同调用同一个包内检查器。 |
| 生成审查可能覆盖已有文件，或使用过宽权限。 | 创建时不覆盖；操作系统支持时默认使用私有权限。 |
| 产品描述可能被误解为自动扫描历史或自动修改。 | 骨架明确记录零来源、覆盖不完整、`analysis-only` 授权和下一步所需权限。 |
| Windows 上的 Python 没有系统 IANA 时区数据库，`Asia/Shanghai` 等有效名称会失败。 | 安装包只在 Windows 安装 `tzdata`，并说明未安装依赖时如何修复。 |

## 快速开始

安装 Release 附带的 wheel，再创建并校验一个骨架：

```bash
python3 -m pip install \
  https://github.com/adand-91/requirement-ledger/releases/download/v0.2.0-alpha.1/requirement_ledger-0.2.0a1-py3-none-any.whl

requirement-ledger review-init \
  --mode audit \
  --target my-agent-skill \
  --start 2026-08-29T00:00:00+08:00 \
  --end 2026-08-30T00:00:00+08:00 \
  --timezone Asia/Shanghai \
  --output /tmp/my-agent-skill-audit.md

requirement-ledger review-check /tmp/my-agent-skill-audit.md
```

预期可观察结果：第一条命令报告 `WROTE_PRIVATE_AUDIT_SCAFFOLD`；第二条报告
`REVIEW_REPORT_VALID`。新文件仍是空审查骨架，不是已经完成的诊断。

## 安全边界与已知限制

本 Alpha 不会扫描 Codex 历史、主目录或 Git 项目；运行时不会联网、运行项目代码、修改目标，
也不会把历史文字当作实施授权。有界上下文必须由 Codex 宿主另行选择并提供。

日报／周报 CLI 初始化、现代 Codex 导出解析、稳定候选延续、报告精确字节交接绑定、定时任务和
自动修改都**不属于**本版本。逐门禁走向稳定 `v0.2.0` 的路径见
[更新地图](https://github.com/adand-91/requirement-ledger/blob/v0.2.0-alpha.1/UPDATE_MAP.zh-CN.md)。

## 兼容性

已发布 v0.1.1 的全部命令与 v1 证据 Schema 保持兼容。新命令是可选入口；类 Unix 系统继续保持
零运行时依赖，Windows 会为 Python 标准库 `zoneinfo` 按条件安装 `tzdata`。
