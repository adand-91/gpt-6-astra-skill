# v0.2.0-alpha.2——有界 Codex 输入

## 解决的问题

通用 v0.1 扫描器接受显式文件，但不能证明一次 Codex 运行始终停在用户批准的导出目录内，也不能
说明哪些物理记录被纳入或排除。调用方还可能把一份文件误认为完整任务历史。

## 用户可见增量

`codex-scan` 只接受一个显式 Codex JSONL 文件，并强制要求范围根、非路径目标／任务引用、带偏移的
半开窗口和 IANA 时区。它只捕获一次来源，从真正参与解析的同一份字节计算摘要，并在普通私有证据包
内嵌 `codex-input-envelope/v1`。

信封只包含固定元数据：摘要、字节数、记录计数、哈希后的目标／任务绑定、窗口元数据、纳入／排除
代码和覆盖状态。它不含来源原文、文件名或路径；外围证据仍属私有，可能含选中的用户原话。

## 安全门禁

- 只接受一个文件，不接受目录或发现模式；
- 范围根不能是文件系统根或用户主目录本身；
- 父级穿越、范围越界、硬链接和普通符号链接／reparse 组件都会失败即停止；
- 捕获上限为 64 MiB，并在读取前后核对身份／内容元数据；
- 输出不覆盖已有文件，平台支持时为 `0600`；
- 刚好等于 `until` 的事件按 `[start,end)` 契约排除；
- 物理记录核算必须平衡，但语义归一化和目标历史完整度仍明确为部分／未知。
- 缺失／非法时间戳、损坏、不支持或超限记录会让选中来源标为不完整，并阻止下游确认。

## 兼容性与限制

v0.1 `scan` 命令和 Schema 继续可用。`codex-scan` 是新增的可选路径；它不会搜索 `~/.codex`、调用
宿主任务 API、归一化所有现代 Codex 事件，也不能证明选中导出包含目标全部历史。POSIX `dir_fd`
保证不可用时，Windows 依赖 reparse 与重复身份核对。
在 macOS，Apple 由 root 持有的 `/var`、`/tmp`、`/etc` 兼容别名会特意映射到固定 `/private`
目标。摘要和解析使用同一份已捕获字节，但并发来源路径稳定性只是基于元数据的尽力检查，不是原子
快照。命令不启动网络客户端，但不会判断所选文件系统是否为远程挂载。
外围 v0.1 证据包的旧字段 `network_used: false` 也只有这一层含义。确定性的目标／任务 SHA-256
用于绑定引用，却不能匿名化低熵值；这类值仍可能被猜中或在多个私有证据包之间关联。

## 发布门禁

只有同一精确 commit 通过 Python 3.10–3.13 × Linux／macOS／Windows 全矩阵，以及构建产物与
失败即停止安全冒烟后，才创建注释 Tag 和公开资产。本版本保持为非 latest 的预发布，不授权推广或
后续版本。
