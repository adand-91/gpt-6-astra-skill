# v0.2.0-alpha.2 — bounded Codex input

## Problem solved

The generic v0.1 scanner accepts explicit files, but it does not prove that a Codex run stayed
inside a user-approved export directory or explain which physical records were included or
excluded. A caller could also mistake one file for complete task history.

## User-visible increment

`codex-scan` accepts one explicit Codex JSONL file and requires a scope root, non-path target and
task references, an offset-aware half-open window, and an IANA timezone. It captures the source
once, hashes and parses those exact bytes, and embeds a private `codex-input-envelope/v1` in the
ordinary private evidence bundle.

The envelope contains only fixed metadata: digest, byte count, record counts, hashed target/task
bindings, window metadata, inclusion/exclusion codes, and coverage states. It contains no source
text, file name, or path. The surrounding evidence remains private and may contain selected user
text.

## Safety gates

- one file only; no directory or discovery mode;
- scope root cannot be a filesystem root or the user home itself;
- parent traversal, scope escape, hard links, and ordinary symlink/reparse components fail closed;
- capture is limited to 64 MiB and identity/content metadata is checked around the read;
- output is no-overwrite and `0600` where supported;
- an event at `until` is excluded by the `[start,end)` contract;
- record accounting is balanced, while semantic normalization and target-history completeness
  remain explicitly partial/unknown.
- missing/invalid timestamps, malformed, unsupported, or oversized records make the selected
  source incomplete and block downstream confirmation.

## Compatibility and limits

The v0.1 `scan` command and schemas remain available. `codex-scan` is a new opt-in path; it does not
search `~/.codex`, call a host task API, normalise every modern Codex event, or prove that the
selected export contains the entire target history. Windows relies on reparse and repeated
identity checks where POSIX `dir_fd` guarantees are unavailable.
On macOS, Apple's root-owned `/var`, `/tmp`, and `/etc` compatibility aliases are deliberately
mapped to fixed `/private` targets. Hashing and parsing use the same captured bytes, but concurrent
source-path stability is only metadata-checked best effort, not an atomic snapshot. The command
starts no network client; it does not determine whether a selected filesystem is remotely mounted.
The enclosing v0.1 bundle's legacy `network_used: false` field has that same narrow meaning.
Deterministic target/task SHA-256 values bind references but do not anonymise low-entropy values;
such values may be guessed or linked across private bundles.

## Release gate

The annotated tag and public assets are created only from the exact commit that passes the full
Python 3.10–3.13 Linux/macOS/Windows matrix plus built-artefact and fail-closed security smoke.
The release remains a non-latest prerelease; it does not authorise promotion or later versions.
