# v0.2.0-alpha.1 — installable named-target audit

This is the first public v0.2 prerelease. It turns the Codex-first review contract into a small,
installable, offline entry point for one explicit target. It is intentionally narrower than the
complete v0.2 plan.

## What changed

- `requirement-ledger review-init --mode audit` creates a private review scaffold for one explicit
  target and one explicit half-open time window.
- `requirement-ledger review-check REPORT` mechanically validates the report schema, window,
  timezone, required sections, evidence labels, candidate state, and authorisation declaration.
- `scripts/check_review_report.py` delegates to the packaged checker, leaving one implementation
  of the validation contract.
- Audit scaffolds start as `analysis-only`, contain zero retrieved sources and incomplete
  coverage, use mode `0600` where supported, and never overwrite an existing file.
- Windows receives a conditional `tzdata` dependency so explicit IANA timezone validation behaves
  consistently across all supported operating systems.
- The bilingual host contract, audit/daily/weekly reference templates, personalisation workflow,
  and ten-day update map make the present boundary and next gates visible.

## Problems this solves

| Before | Alpha 1 |
| --- | --- |
| A user could name a Skill or project but had no installable, target-specific review starting point. | One command creates a target- and time-bound audit document with explicit unknowns. |
| A Markdown review could look complete while omitting required evidence or safety fields. | A zero-dependency checker returns a failing exit code and actionable findings. |
| Validation logic could drift between a script and the installed package. | Both entry points use the same packaged checker. |
| A generated review could overwrite an existing file or be created with broad permissions. | Creation is no-overwrite and private-by-default where the operating system supports it. |
| Product language could be mistaken for autonomous history scanning or editing. | The scaffold records zero sources, incomplete coverage, `analysis-only` authority, and the exact next permission needed. |
| Python on Windows has no system IANA timezone database, so valid names such as `Asia/Shanghai` failed. | The package installs `tzdata` only on Windows and explains how to repair a no-dependency install. |

## Quick start

Install the attached wheel, then create and validate a scaffold:

```bash
python3 -m pip install \
  https://github.com/adand-91/requirement-ledger/releases/download/v0.2.0-alpha.1/requirement_ledger-0.2.0a1-py3-none-any.whl

requirement-ledger review-init \
  --mode audit \
  --target my-agent-skill \
  --start 2026-08-29T00:00:00+08:00 \
  --end 2026-08-30T00:00:00+08:00 \
  --timezone Asia/Shanghai \
  --output /tmp/my-agent-skill-audit.md

requirement-ledger review-check /tmp/my-agent-skill-audit.md
```

Expected observable result: the first command reports `WROTE_PRIVATE_AUDIT_SCAFFOLD`; the second
reports `REVIEW_REPORT_VALID`. The new file is still an empty review scaffold, not a completed
diagnosis.

## Safety boundary and known limits

This Alpha does not scan Codex history, the home directory, or a Git project. It does not use the
network at runtime, run project code, edit a target, or treat historical text as implementation
authorisation. A Codex host must separately select and supply the bounded context.

Daily/weekly CLI initialisation, modern Codex export parsing, stable candidate carry-over,
exact-byte report handoff binding, scheduling, and autonomous edits are **not** part of this
release. See the [update map](https://github.com/adand-91/requirement-ledger/blob/v0.2.0-alpha.1/UPDATE_MAP.md)
for the gate-driven path to stable `v0.2.0`.

## Compatibility

All released v0.1.1 commands and v1 evidence schemas remain compatible. The new commands are
opt-in. Unix-like systems keep zero runtime dependencies; Windows installs `tzdata` conditionally
for Python's standard-library `zoneinfo` support.
