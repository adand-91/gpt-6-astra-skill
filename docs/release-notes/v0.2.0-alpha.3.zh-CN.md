# v0.2.0-alpha.3 候选——现代 Codex rollout 归一化

状态：本地候选；尚未 commit、Tag、push 或公开发布。

## 解决的问题

Alpha 2 已能安全绑定一份选中的 Codex 导出，但语义适配器只理解很窄的旧事件界面。当前分页
rollout 会持久化结构化 `item_completed` 生命周期记录；同一项目可能出现重复快照，
`task_complete` 后也可能追加迟到项目。如果把每个快照都当成新事件，或从自然语言推断“完成”，
就会生成失真的历史。

## 用户可见增量

`codex-scan` 现在输出 `codex-input-envelope/v2`，其中含
`codex-modern-normalization/v1`。对本候选实现的官方 TurnItem 白名单，它会：

- 保留每个完成项目第一次出现的物理记录位置；
- 按 `(turn_id, item.id)` 合并重复快照，由最后一份合法快照提供最终结构化状态；
- 同一 item ID 位于不同 turn 时仍分别保留；
- 把 `task_complete` 记录为有序 turn 终点，但不声称其后一定没有迟到项目；
- 绝不按内容给普通消息或工具事件去重，也绝不从自然语言猜测完成；
- 用平衡的物理记录核算，准确记录结构化 automation、delegation、Subagent、system 和非证据
  元数据排除项。

元组身份使用规范 JSON 编码，而不是分隔符拼接。带控制字符的 ID、未来或畸形 `UserInput`
块、非法状态／类型组合，以及不能与已识别记录守恒的归一化计数，都会失败即停。工作边界是
64 MiB 和 1,000,000 条物理记录。

信封只保存固定项目类型／状态、物理位置、时间戳、计数和绑定来源的不透明标识；不保存原始 turn／
item ID、命令、输出、Skill 名、Skill 路径、文件名、绝对路径或来源原文。

## 点名 Skill 证明

候选 fixture 使用官方 `UserInput::Skill` 结构，按真实本地 Skill 形状点名，并同时带一段文字要求。
按设计，私有证据可以保留选中的用户文字；非文本信封不会保留 Skill 名称或路径。这是维护者自有
fixture，不是外部用户采用证据。

## 兼容性与限制

- 冻结的 v0.1 `scan` 命令继续使用旧解析器，并保留 `--until` 闭区间行为。
- `codex-scan` 保留 Alpha 2 的单文件、64 MiB、范围约束、半开 `[start,end)`、同字节绑定和不覆盖
  边界。
- 即使没有触发字节上限，超过 1,000,000 条物理记录也会停止。
- 未知记录类型、未知 TurnItem、非法最终状态、损坏记录、时间戳失败、预算丢弃或标识／类型冲突，
  都会把来源标为不完整。
- 归一化器保留 JSONL 物理顺序；不会按可选 rollout ordinal 重排，也不声称已规范重建整条任务历史。
- 白名单跟随当前第一方协议结构，并明确标为 `partial-alpha.3`；Codex 协议非穷尽，仍会演进。
- 确定性不透明 ID 只用于私有绑定，不保证匿名；低熵值仍可能被猜测或跨证据关联。
- 一份选中导出不等于目标完整历史。本候选不会发现任务、读取 `~/.codex`、调用宿主历史 API，
  也不会授予实施或发布权限。
