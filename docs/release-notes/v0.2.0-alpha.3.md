# v0.2.0-alpha.3 candidate — modern Codex rollout normalisation

Status: local candidate; not committed, tagged, pushed, or published.

## Problem closed

Alpha 2 bound one selected Codex export safely, but its semantic adapter understood only a narrow
legacy event surface. Current paginated rollouts persist structured `item_completed` lifecycle
records, can repeat snapshots for the same item, and may record a late item after `task_complete`.
Treating every snapshot as a new event or inferring completion from prose would produce a false
history.

## User-visible increment

`codex-scan` now emits `codex-input-envelope/v2` with a
`codex-modern-normalization/v1` section. For the official TurnItem allowlist implemented by this
candidate, it:

- preserves the first physical-record position of each completed item;
- coalesces repeated snapshots by `(turn_id, item.id)` and lets the latest valid snapshot supply
  the final structured status;
- keeps the same item ID in different turns separate;
- records `task_complete` as an ordered turn terminal without claiming that no late item follows;
- never content-deduplicates ordinary messages or tool events and never infers completion from
  natural language;
- records exact structured automation, delegation, Subagent, system, and non-evidence metadata
  exclusions with balanced physical-record accounting.

Tuple identity is encoded as canonical JSON rather than delimiter concatenation. Control-bearing
IDs, future or malformed `UserInput` blocks, invalid status/type pairs, and normalization counts
that do not conserve against recognized records fail closed. The work boundary is 64 MiB and
1,000,000 physical records.

The envelope stores only fixed item kinds/statuses, physical positions, timestamps, counts, and
source-bound opaque identifiers. It does not store raw turn/item IDs, commands, outputs, Skill
names, Skill paths, file names, absolute paths, or source text.

## Named-Skill proof

The candidate fixture uses an official `UserInput::Skill` block naming a real local Skill shape
alongside a text instruction. The private evidence can retain the selected user text, as designed;
the non-textual envelope retains neither the Skill name nor its path. This is a maintainer-owned
fixture, not external-user adoption evidence.

## Compatibility and limits

- The frozen v0.1 `scan` command keeps its legacy parser and inclusive `--until` behaviour.
- `codex-scan` keeps Alpha 2's one-file, 64 MiB, scoped, half-open `[start,end)`, same-byte,
  non-overwrite boundary.
- It additionally stops above 1,000,000 physical records, even if the byte cap is not reached.
- Unknown record types, unknown TurnItem types, invalid final statuses, malformed records,
  timestamp failures, budget drops, or identifier/type conflicts mark the source incomplete.
- The normaliser preserves physical JSONL order; it does not reorder records by optional rollout
  ordinal or claim a canonical full-thread reconstruction.
- The allowlist follows current first-party protocol shapes and is explicitly
  `partial-alpha.3`; Codex remains non-exhaustive and can evolve.
- Deterministic opaque IDs are private binding aids, not anonymity guarantees. Low-entropy values
  may remain guessable or linkable.
- One selected export is not complete target history. This candidate does not discover tasks,
  read `~/.codex`, call a host history API, or grant implementation/publication authority.

## Publication state

Passing local source, build, clean-install, privacy, and security gates does not create a public
version. A separate maintainer decision for an exact commit is required before commit, push, tag,
GitHub Release, promotion, or programme application.
