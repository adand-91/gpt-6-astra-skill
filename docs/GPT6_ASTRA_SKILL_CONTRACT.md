# Astra Skill Optimizer 项目契约

## 项目名称

- 产品名：**Astra Skill Optimizer**
- GitHub 仓库：`gpt-6-astra-skill`
- `Astra` 是本项目统一拼写；“Astro”视为同一名称的误拼，不建立第二个品牌。

## 核心定位

新一代模型发布后，旧 Skill 中的约束、流程和提示词可能失真：它们可能限制模型能力、制造多余确认、破坏工具协作，或者让原本有效的工作流失效。

Astra Skill Optimizer 专门发现这些失真，并把现有项目的 Skill 和流程调整为在 GPT-6 及 Astra 环境下可用、可验证、可继续维护的版本。

## 短期目标

针对用户手头的一个明确项目及其关联 Skill：

1. 恢复项目目标、当前阶段和真实证据。
2. 检查 Skill 是否仍适合 GPT-6/Astra 的能力与交互方式。
3. 找出旧约束、触发失败、主动性不足、格式失真和验证缺口。
4. 提出最小、可回滚的优化。
5. 用原失败案例、成功案例和边界案例验证修改前后差异。
6. 记录来源、版本、证据、变更和下一步。

## 长期愿景

把它发展成类似 Jarvis 的个性化 Skill 优化系统：用户提出自己的工作目标，系统识别其使用的 Skill、习惯和失败反馈，持续生成适合个人与模型版本的改进建议，并帮助维护一套可复用、可验证的 Skill 资产。

长期能力包括：

- Skill 版本与适用模型管理
- 不同模型版本的兼容性测试
- 失败案例回放和边界测试
- 个性化工作流适配
- 来源、变更和回滚证据
- 面向开源社区的 Skill 共享、评审和协作
- 新模型发布后的迁移提示与升级路径

## 纯粹性边界

本项目只处理 GPT-6/Astra 的 Skill 与流程适配，不纳入：

- 接单、报价、客户沟通或订单记录
- 币圈量化、交易账户或资金决策
- 某个业务项目的具体代码和私有数据
- 私人聊天、客户附件和未脱敏工作记录
- 无边界的全盘 Skill 扫描
- 未经授权的自动修改、提交或发布

具体业务项目只作为脱敏、明确授权的适配输入，不成为本项目的产品内容。

## 版本边界

当前仓库的旧包名和 CLI 命令保留为兼容入口，改名迁移期间不得破坏已有安装和测试。新的公开产品名、仓库名、文档入口和插件说明统一使用 Astra Skill Optimizer。

项目改名、包与 CLI 迁移、公开发布和社区推广分别验收，不把其中一项当成其他项已经完成。

## 完成标准

短期版本完成的标志是：给定一个选定项目和相关 Skill，系统能输出证据明确的适配结论、最小修改方案、正反边界验证和唯一下一步，并证明业务项目内容没有被写入产品本身。

长期版本完成的标志是：社区用户可以提交 Skill 和失败案例，获得可复核的模型适配建议、变更差异、测试结果和可回滚版本。
