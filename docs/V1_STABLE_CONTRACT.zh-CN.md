# Requirement Ledger v1.0 正式版契约

状态：运行时／schema 契约已于 2026-08-30 通过本地 Beta／RC／Stable 发布列车验收。
`1.0.0` 候选在 2026-08-31 因 Codex 首用路径与已安装插件快照问题重新开启狭义资格验证；这不表示
运行时或 schema 发生改变。

## 产品结果

Requirement Ledger v1.0 是一个隐私优先、离线运行的证据与复盘工具，只处理一个被明确选择的
Codex 任务、Agent Skill、Git 项目或有界导出。正式版由两层组成：

1. 稳定的 Python 库与 CLI，唯一负责 schema、校验、隐私边界、候选项延续、报告绑定和确定性验收；
2. 符合 Codex 结构的轻量纯 Skill 插件，引导宿主调用已经安装的 CLI。

插件只是分发和工作流入口，不是第二套实现。v1 插件不包含 MCP、App、Hook、插件自有认证实现／
凭据流、下载器、安装器、模型调用、数据库、遥测或联网依赖。marketplace 必需的
`policy.authentication: ON_INSTALL` 是 Codex 宿主认证时机策略元数据；插件不提供认证方法，
也不处理凭据。

插件刻意提供两个不同级别。Codex 宿主已选快速审查是即时、仅分析、`host-selected / unbound` 的
决策辅助，不创建 CLI 产物；证据绑定审查使用明确文件和下面的 CLI 链。只有第二级才能声称当前来源包、
报告、候选状态或交接身份已经绑定。

## 决策状态

### 已确认

- 本地发布列车以通过机械验收的 `1.0.0` 候选版为终点。
- 独立 CLI／库仍是产品核心。
- Codex 分发层采用仓库内 marketplace 加纯 Skill 插件。
- 宿主已选快速审查与证据绑定 CLI 审查是两个不同级别，不能互相冒充。
- 输入必须由用户明确选择，或由能够证明选择范围有界的宿主提供；工具不发现全部历史或全部项目。
- 分析不授权实施、提交、发布、计划任务或其他外部动作。
- 本次本地列车不包含 commit、push、Tag、GitHub Release、推广、项目申请、公开目录提交或外发消息。

### 工程决策

最短且每版都有价值的列车是 `0.2.0b1` → `0.2.0b2` → `1.0.0rc1` → `1.0.0`。
禁止为了凑版本号发布空更新；每个预发布版都必须关闭一个用户可见的验收缺口。

### 需要另行授权

公开插件提交需要以后单独决定，并补齐已验证的发布者身份、可供审核的公开元数据、隐私／条款／
支持链接，以及提交和发布授权。本地通过校验不等于获得公开审核批准。

## 正式版用户链路

Codex 优先的快速路径是：

```text
一个由宿主选中的任务／项目
  → 人话目标／阶段／问题／保留项／第一项改动／下一步
  → host-selected / unbound / analysis-only
```

它不要求虚构时间窗或私有文件路径，但也不会形成机械绑定的审查。证据绑定路径是：

```text
明确目标与时间窗
  → 授权范围目录内的明确文件
  → 私有、哈希化的来源包
  → audit／daily／weekly 仅分析复盘
  → 私有候选项延续状态
  → 最终报告及报告字节／来源／状态头绑定
  → 只读交接复核
  → 宿主获得独立授权后实施
  → 使用同一验收口径验证结果
```

任何一步都不会悄悄授予下一步的权限。

## 版本门

### `0.2.0b1`——可用的复盘周期

- `review-init` 支持 `audit`、`daily`、`weekly`。
- 保留显式起止时间窗。
- daily／weekly 可根据明确 IANA 时区、参考时刻和本地边界小时计算窗口。
- 覆盖夏令时、跨月／跨年、恰好位于边界、无效时区和无效小时测试。
- 脚手架仍为零来源、私有、仅分析，并通过同一个报告检查器。

### `0.2.0b2`——可追溯延续与 Codex 分发

- 私有候选账本使用稳定不透明 ID、明确状态转换表、确定性状态头、目标绑定、过期头拒绝、精确延续，
  且不静默去重或丢项。
- 私有来源包只按摘要和字节数绑定授权范围内被明确点名的输入，不保存原文或本机路径。
- 仓库内 marketplace 提供轻量纯 Skill Codex 插件；插件只预检已安装 CLI 版本，不安装或升级任何软件。

### `1.0.0rc1`——冻结正式表面

- 最终报告可以绑定其精确字节、来源包、目标、候选状态头和复盘元数据。
- 只读交接检查重新打开所有明确输入，拒绝任何变化，不写文件，并输出稳定的可交接／不可交接结果。
- 私有输出使用禁止覆盖写入，在支持的平台采用严格权限。
- v0.1 和 Alpha 3 的旧命令与 schema 继续通过既有测试。
- RC 通过本地受支持的 Python／操作系统目标、干净 wheel／sdist 构建、干净安装、隐私检查和插件
  校验。跨平台 CI 已配置，但公开 Linux／Windows 矩阵属于以后发布门，不能用本机跳过结果代替。

### `1.0.0`——稳定晋级

- RC 后不增加功能；只允许调整发布元数据和文档。若修改代码，必须先重建并重新验收 RC。
- 本地源码套件收集 194 项：187 通过，七项 Windows 原生测试在 macOS 明确跳过。解包 sdist
  同样收集 194 项，其中三项仓库专属插件检查及七项 Windows 原生检查被明确跳过。
- 最终 wheel、sdist、源码快照、测试数、烟测结果和 SHA-256 记录在本地发布证据目录。
- 使用维护者自有的 audit／daily／weekly 三条有界链路和插件正负用例验收，确保没有广泛发现、
  没有把私有原始证据贴进对话、没有自动改文件或外部动作。

## 规范性安全与兼容规则

- 范围根目录不能是文件系统根目录或用户主目录。
- 输入必须是范围根目录之下被明确点名的普通文件；链接、父目录穿越、硬链接、读取中替换和重复别名
  一律失败关闭。
- 所有私有 schema 都限制大小与数量，并拒绝未知或格式错误的控制字段。
- 私有机器状态只保存目标摘要。摘要只能证明字节身份，不能证明事实、作者、质量或授权。
- 候选项只按宿主提供的不透明 ID 精确匹配；v1 不做语义合并。
- 当前输入中缺失但仍未关闭的候选项会被明确标为延续，不会静默丢弃。
- 绑定报告必须是 `status: final`、通过机械检查，并绑定当前明确来源；绑定动作不授权实施改动。
- 插件以 `requirement-ledger --help` 作为已安装命令的权威。CLI 缺失或版本不兼容时明确停止，
  插件绝不自动安装软件。
- 宿主已选快速审查不调用 `review-init`，也不声称已有绑定。v1 中，证据绑定 CLI 的
  `review-init --mode audit` 仍要求明确起点、终点和时区。
- 编辑本地 marketplace checkout 不能证明 Codex 已加载哪个版本化 Skill 快照。资格验证必须刷新
  已安装插件、新建任务并复验当前契约，才能声称插件路径通过。
- Python CLI 与 Codex 插件是两个独立分发层，互不嵌入。
- Windows 输出采用绑定父 `HANDLE`、`NtCreateFile(RootDirectory=...)`、受保护 DACL 和纯
  HANDLE 回滚。Windows 原生运行证据必须来自 Windows runner，macOS 契约测试不能冒充该证据。

## 正式版排除项

v1 不包含自动发现任务／历史、后台监控、联网趋势采集、模型评分、候选项语义匹配、自动修改项目、
自动提交／推送／发布、GUI、托管服务、数据库、远程 trace、OAuth、MCP、Apps SDK 组件，
也不保证 IDE 扩展支持。

## 调研依据与复用边界

- OpenAI 插件文档确认纯 Skill 插件、必需的 `.codex-plugin/plugin.json` 和仓库内 marketplace；
  MCP 面向实时外部能力、认证或受控远程工具，本项目不需要。
- `openai/codex` 的可借鉴点是持久记录、可见摘要、检查点和显式状态转换分层；v1 不嵌入 Codex 内部实现。
- `anthropics/skills` 只用于打包调研，不是本项目运行时或标准。Requirement Ledger 以 Codex 为先，
  在指令文本之外提供确定性 CLI，不依赖 Claude 专属 Hook／插件／配置，也不复制 Anthropic Skill 文本
  或许可不一致代码。这是架构差异，不是对宿主整体质量的空泛结论。
- `promptfoo/promptfoo` 的可借鉴点是可重复机器检查加人类报告；不引入其供应商、模型执行、Web UI 或运行时。
- `Arize-ai/phoenix` 的可借鉴点是原始事件与派生摘要分层；不引入遥测、数据库、远程 MCP、部署设施
  或 Elastic 许可代码。
- `openai/openai-apps-sdk-examples` 展示了窄工具契约，但其 MCP／组件运行时会扩大 v1 权限面，因此排除。

只复用公开的架构思想，不引入任何外部运行时或源码。
