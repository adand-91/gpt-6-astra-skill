# v0.1.0 — Installable evidence loop

Status: release candidate. Local pre-release gates passed on 2026-08-28; the public tag and
GitHub Release wait for the release commit's cross-platform CI to pass.

## What changed

- Requirement Ledger has grown from a transcript-retrospective Skill into an installable,
  privacy-first evidence and repair-planning pipeline for any Git project.
- `requirement-ledger doctor`, `scan`, `analyze`, `report`, `suggest`, `verify`,
  `privacy-check`, and `demo` form the v0.1 CLI.
- The new path accepts only an explicit repository and explicit transcript/test-log files.
- Git collection is fixed and read-only; remotes are not inspected.
- Private raw evidence, analysis, share reports, repair drafts, and validation results have
  separate versioned states.
- Attribution is conservative: `upstream`, `project-local`, `personal`, or `unknown`, with
  `unknown` as the default when confirmation evidence is absent.
- Share reports exclude quotes and local identifiers, then pass through an automated privacy
  check that never claims to replace human review.
- Repair plans are always `DRAFT — NOT SENT` and `not-applied`.
- The CLI does not run project code, install dependencies, access a network, edit a worktree,
  commit, push, create Issue/PR/Release, upload, or emit telemetry.

## Compatibility

The original `scripts/scan_transcript.py`, retrospective report checker, translation checker,
templates, and references remain in the source distribution. Legacy scanner output is private;
`--no-text` does not make it safe to share.

## Verified release-candidate evidence

- All repository tests pass locally.
- Python sources compile.
- English/Chinese normative mirrors are in sync.
- Wheel and sdist build; the wheel installs without runtime dependencies in a clean Python 3.12
  virtual environment.
- The installed console command reports `0.1.0`.
- Two installed synthetic demo runs are byte-identical.
- The sdist contains the Skill, bilingual core docs, references, templates, scripts, examples,
  tests, architecture, threat model, maintenance policy, release checklist, context, and handoff.
- An explicit-input smoke run on the project leaves its Git status byte-for-byte unchanged.
- The privacy canary returns a blocking status without printing matched values.

Cross-platform Python 3.10–3.13 results are the final public gate after the release-candidate
commit is pushed.

## Known limitations

- v0.1 produces candidates and plans; it does not safely execute or apply repairs.
- Test-log parsing is a conservative text adapter, not yet structured by test framework.
- Clean-room reproduction and authorised personal-configuration comparison are not automated,
  so most scopes remain `unknown` until a human supplies the missing evidence.
- Pattern-based privacy detection has false positives and false negatives.
- Provider formats may drift; only synthetic fixtures are shipped.
- Daily/weekly reporting, adoption records, isolation, object-bound approvals, transactional
  apply, rollback, signed artefacts, and provenance remain future work.

The complete list stays visible in `docs/PROJECT_GAPS.md`.
