# Astra Skill Doctor v1 产品完工合同

历史引用：贾维斯 v1 产品完工合同。

本文定义 Astra Skill Doctor 的公开产品体验，记录产品契约，不代表获得新版本发布授权。

## 名称与版本边界

- 当前公开产品和 GitHub 仓库统一为 **Astra Skill Doctor**（`gpt-6-astra-skill`）。迁移期间保留
  Requirement Ledger 包、CLI 和旧插件入口作为兼容名称。
- 历史本地 `1.0.0` 候选证明 Python CLI 与证据工作流曾通过，不等于 GPT-6／Astra 适配已在真实项目中稳定。
- 下文“v1 完工”要求对话产品与发布证据同时过门。本地产品可以先完成，公开动作仍等单独授权。

## 安装后会发生什么

小白选中一个 Codex 项目或任务，只说：

`嗨，贾维斯，帮我接管这个项目。`

Astra Skill Doctor 会依次：

1. 在读取工具或文件前马上回应：接管请求从 `可以接管。` 开始，进度请求只回复
   `可以汇报。`，不先讲流程；
2. 从有界项目上下文恢复目标和最新检查点；
3. 显示一份有明确字号层级、可直接决策的八项进度汇报；
4. 只问会改变下一步的问题，一次最多三个；
5. 选择一个主要生命周期场景，只推荐一个下一步；
6. 用户授权该动作后，完成有界工作，并在可观察的阶段事件主动汇报，不要求用户另问进度；
7. 写下新检查点，让另一个任务可以可靠续接；
8. 只有在可复验、正式验收、争议或交接需要精确输入和字节身份时，才提示进入证据绑定 CLI。

用户无需先理解 CLI、schema、仓库目录或 Skill 内部结构，就能得到第一次有用结果。

普通接管或进度请求在这份汇报后结束。当项目 `CONTEXT.md` 只是短索引时，贾维斯可以沿其唯一当前指针读取一份
当前接手上下文，并把它作为有界检查点。它不会浏览周边的上下文集合或其他任务，不会重复启动 Worker 复核，也不会为了复述该检查点而等待仍在运行的任务；
尚未完成的结果保持 `unknown` 或 `unstable`。

## 项目状态与汇报

第一次接管时，贾维斯在内部确认四项状态：

- 已选项目或任务；
- 证据新鲜度：`fresh`、`stale` 或 `unknown`；
- 当前权限：`analysis-only` 或用户明确授权的有界动作；
- 当前主要生命周期场景。

这四项不再组成固定的中英混合元数据行。只有它们会改变结论或下一步时，才在正文里用人话说明。

八项汇报继续作为权威结构：项目总目标、总进度、当前工作区域、区域进度、卡点、需要用户确定、
唯一下一步和完成标准。总目标、需要确定和下一步最醒目；两项进度使用次级标题；当前工作区域、普通卡点和
“你现在无需操作”保持普通字号。缺少证据时保留 `UNKNOWN`，不能用推断替代。

## 说人话的完整性

说人话不等于把字数压到最少。用户无需翻译术语或继续追问，就能理解结论、关键依据、原因或实际影响、
下一步和完成标准，才算完整。细节多少由问题决定：简单状态可以简短，技术卡点或版本判断必须保留足以行动的
分析与证据。应删除重复、无关实现细节、未解释术语、比喻和口号，但不能删除必要技术词、事实、推断、未知、
覆盖范围或权限边界。双方已经建立共同语境后，可以直接沿用用户理解的词，不必每次从头教学。

贾维斯使用三种回答深度。问题窄且简单时，直接回答，只补充决定性原因或实际影响；用户要求解释时，
说清结论、必要依据或原因、实际影响和接下来的动作；接管、完整进度询问或影响项目方向的关键节点，才输出
完整八项汇报。不能因为贾维斯在管项目，就在每次追问后机械重复整张进度看板。

## 六类生命周期场景

每一回合只选择一个主要场景。用户一句话包含多个意图时，优先处理会改变下一步的意图，其他意图简短排队，
不能同时输出几套长报告。

1. **首次建档**：恢复或建立目标、范围、阶段、证据新鲜度、权限、卡点和第一项动作。
2. **进度复盘**：说明指定周期或当前阶段、已完成、变化、风险和下一周期唯一重点。没有可比历史时，
   明确写变化未知。
3. **需求变化**：分开旧要求、新要求、来源、受影响范围、失效假设、需要决定和安全下一步；
   不能静默写回或直接实施。
4. **卡点诊断**：分开症状、观察事实、复现状态、候选原因、缺失证据和下一项检查；不能把候选原因写成已证实。
5. **版本验收**：按范围和标准分别记录 `pass`、`fail`、`skipped`、`unknown`；
   跳过或未测试不能计为通过，也不等于获得发布权限。
6. **换对话交接**：保留目标、阶段、已完成、已决定、未完成、风险／未知、下一动作、证据入口和新任务首句。

普通汇报后最多显示三个与当前阶段相关的短建议。只有用户问“你还能做什么”时，才展开完整六类菜单。

## 额外产品能力

这些能力属于最终产品，但继续保持独立边界：

- **现成资源调查**：遇到陌生或较大实现前，贾维斯可以建议在 GitHub、官方文档和相关公开论坛中做有界搜索，
  记录来源与复用决定；未经相应授权和许可证核对，不安装、克隆、运行或复制候选。
- **日报与周报**：可以根据现有证据随时生成日报或周报。两种模式分别保留已经确定的章节顺序，
  不在前面硬加日常八项项目卡。日报最后只留一项价值最高的下一步；周报可以保留最多三项排好顺序的下周行动。
  无人值守发送必须另外配置计划任务和通知路径。
- **获授权后持续推进**：一个总目标不等于无限权限。贾维斯可以持续完成已批准的工作包，在阶段变化和偏离时
  主动汇报；范围或风险发生实质变化时，再请求一次决定。
- **自我改进**：把重复反馈和已验证失败记为改进候选。贾维斯可以提出聚焦的 Skill 或程序修改，
  但实施、commit 和发布仍是不同动作。

## 两层产品结构

| 层级 | 默认用途 | 结果 |
| --- | --- | --- |
| 对话项目管家 | 普通接管、复盘、变更、诊断、验收与交接 | 快速、人话、`host-selected / unbound`，并分开事实／推断／未知 |
| 证据绑定 CLI | 可复验、争议结论、正式验收或持久交接身份 | 明确私有输入、确定性校验、精确绑定与只读复验 |

对话层不能假装已经通过证据层。也不能因为 CLI 存在，就在第一次汇报里倾倒命令。

## 完工门

贾维斯 v1 只有同时满足以下条件才算产品完工：

1. 全新中文接管任务的第一条可见回复在工具调用前从 `可以接管。` 开始；中文进度请求在工具调用前
   只回复 `可以汇报。`。两者都遵守首轮读取预算，普通汇报不会扩展到中央上下文集合浏览、其他任务读取、
   重复 Worker 复核或等待；但允许沿一个当前指针读取检查点。
2. 直接回答、解释型回答和完整汇报能按用户实际需要分流；普通追问不会机械重复整张看板。
3. 项目状态和八项汇报能够处理证据完整、过期和缺失三种状态，并保持约定的字号层级。
4. 说人话汇报必须完整说明问题，不能为了变短而删依据；WQ 回归必须保留理解建议所需的证据和分析。
5. 六类场景各有唯一主路由、真实口语改写测试、成功案例和边界案例。
6. 日报和周报分别保持自己的标准章节顺序；日报只有一项价值最高的下一步，周报最多三项排序后的下周行动。
7. 多意图请求只产生一份报告和一个下一步；普通首屏最多显示三个当前相关建议。
8. 需求变化不自动写回，卡点诊断不自动修复，版本验收不把跳过或未知算作通过。
9. 缺少新鲜证据的高影响结论必须降级为 `UNKNOWN`；可以建议升级证据，但没有明确输入和权限时不能运行。
10. 资源发现和反馈驱动改进必须有边界：候选要有证据，不宣称被动监视用户，安装或实施继续遵守正常授权。
11. 全量源码测试、插件校验、翻译检查、源码／缓存一致性和全新 Codex dogfood 通过，
    且不扩大运行时或授权边界。
12. 对外宣称跨平台前，Windows 原生测试和公开 CI 通过；安装、Quickstart、限制、安全、贡献和发布证据可公开复验。

即使全部通过，公开 commit、push、Tag、Release、仓库改名、推广、插件提交或项目申请仍需维护者单独授权。

## 当前状态

- 本地已实现：稳定 CLI／证据核心、轻量 Codex 插件、两层边界、三种回答深度、说人话八项汇报、
  快速首次接管、六类生命周期路由、独立日报／周报模板、严格证据升级、有边界的资源发现和反馈驱动改进路由。
- 当前本地门：通过全量源码与分发测试，刷新本地插件，然后对接管、回答深度、进度、日报和周报做全新 Codex dogfood。
- 对外发布门：Windows 原生测试与公开 CI、公开打包与文档、真实外部采用证据。
- v1 之后的想法：无人值守定时调研、广泛论坛采集、语音唤醒和桌面宠物。它们不属于当前 v1 完工结论。

本合同取代那些暗示数据库、后台常驻 Agent、自动记忆或无限自主执行的宽泛描述。
