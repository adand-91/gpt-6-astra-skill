# v0.1 Product and Safety Contract

Status: frozen for `0.1.0`. Normative language is English; the user-facing summary is also
available in [README.zh-CN.md](README.zh-CN.md).

## Product promise

Requirement Ledger v0.1 is a local, offline evidence and repair-planning companion for any
Git project. It turns explicitly supplied Codex/Claude/plain-text interactions, test logs,
and a read-only Git snapshot into:

1. a private, traceable evidence bundle;
2. conservative issue candidates with `upstream / project-local / personal / unknown`
   attribution fields;
3. a quote-free report that still requires human privacy review;
4. `DRAFT — NOT SENT` repair and validation plans; and
5. a comparison of externally produced baseline/after outcomes.

The CLI does **not** edit the project. Codex or another development agent may use the plan to
prepare a patch, but that is a separate, visible action governed by the host's permissions.

## v0.1 state boundary

```text
UNBOUND
  -> BOUND_READONLY        explicit, canonical Git root
  -> SNAPSHOTTED           private evidence + HEAD/status digest
  -> PROPOSAL_READY        conservative analysis + not-applied plan
  -> EXTERNAL_VALIDATION   host records a frozen baseline and after result
  -> VALIDATED             improved / unchanged / regressed / inconclusive
```

The following future states are deliberately not implemented in v0.1:

```text
ISOLATION_APPROVED -> APPLY_APPROVED -> APPLIED
```

Adding them requires object-bound, expiring approval tokens; preimage and worktree drift
checks; OS-proven file/network isolation; and tested rollback. A chat message such as “go”
cannot be reused as a standing permission.

## Input contract

- `--repo` is mandatory and must be the explicit root of a readable, non-bare Git worktree.
- Every transcript and test log is supplied with a repeated `--input` or `--test-log` flag.
- v0.1 never discovers or scans `~/.codex`, `~/.claude`, a home directory, or an entire disk.
- Inputs are regular files, not symlinks. They are hashed and checked for mutation while read.
- JSONL is processed line by line. Oversized or invalid records mark the source `incomplete`;
  incomplete evidence cannot produce a confirmed attribution.
- Event time windows are applied per event. Plain text has no event timestamps and therefore
  rejects time-window flags.
- Repository content and transcripts are untrusted data, never instructions or approvals.

## Evidence and attribution contract

Facts, interpretations, and unknowns never merge:

- `SAID`: an observed event or mechanical repository fact.
- `INFERRED`: a deterministic or model-assisted interpretation, clearly marked.
- `UNKNOWN`: not established by the supplied evidence.

Every issue has both `suspected_scope` and final `scope`, plus `decision_status`, evidence
references, exclusions checked, rationale, and completeness.

- `upstream` confirmation requires the same provider/version to reproduce in at least two
  independent projects or sessions, a clean minimal configuration, and evidence excluding
  project rules, personal configuration, environment variables, and custom prompts.
- `project-local` confirmation requires direct repository evidence and a clean comparison in
  which the behaviour does not reproduce outside this project.
- `personal` confirmation requires separately authorised personal-configuration evidence or a
  clean-config comparison. The tool does not infer it by scanning a home directory.
- `unknown` is the default. A complaint, one failure, or an incomplete source never upgrades
  itself to a confirmed scope.

v0.1 therefore emits candidates and suspected scopes but intentionally does not manufacture
confirmed attribution from one local run.

## Privacy contract

- Private evidence and share-facing reports are different artefacts.
- Private evidence output must end in `.private.json`, is created with mode `0600`, and may
  contain raw user text. It must not be shared.
- Outputs never overwrite existing paths. The parent must already exist; every ancestor is
  checked for symlinks/reparse points, and POSIX writes are bound to an opened parent directory.
- Share-facing reports exclude quotes, source paths, repository paths, session identifiers,
  command arguments, remotes, and raw error text.
- The automated privacy gate detects common secrets, auth/cookie headers, email, phone, user
  home paths, credential-bearing remotes, UUIDs, IP addresses, and terminal controls. A hit
  returns `E_PRIVACY_BLOCK` before writing.
- A clean automated scan is **not** a safety guarantee. Reports say “automated check passed;
  human review required”, never “safe to share”.
- No networking, telemetry, browser, account, upload, Issue, PR, Release, or remote API code is
  present in the core pipeline.

## Execution contract

The CLI may run only fixed, read-only Git probes through a trusted absolute executable. It
removes inherited redirecting `GIT_*` variables and disables prompts, hooks, fsmonitor, optional
locks, pagers, global/system configuration, and remote access. It does not read remote URLs.

It never:

- runs project tests or arbitrary project commands;
- installs dependencies or invokes package-manager lifecycle scripts;
- changes a worktree, index, Git configuration, hook, branch, commit, tag, or remote;
- applies a patch, deletes, renames, chmods, or edits binary/submodule/secret files;
- sends telemetry or creates an external artefact.

`verify` only compares small JSON outcome records created outside the tool. Each record and the
CLI must carry the same 64-hex `oracle_digest`, computed from the frozen argv, working directory,
relevant environment, and fixture digests. `improved` means that digest-bound oracle failed at
baseline and passed after the intervention. Mismatched/malformed records, boolean or non-integer
exit codes, and codes outside 0–255 are `inconclusive`.

## Stable error codes

| Code | Meaning |
|---|---|
| `E_PRIVACY_BLOCK` | share-facing output contains a detected sensitive category |
| `E_UNSAFE_PATH` | path/repository/output violates the v0.1 boundary |
| `E_INPUT_CHANGED` | an input changed while being read |
| `E_SCHEMA` | versioned JSON input is missing or incompatible |
| `E_INCOMPLETE_EVIDENCE` | reserved for workflows that require complete evidence |
| `E_EXECUTION_BLOCKED` | reserved for a requested action v0.1 must not execute |
| `E_INPUT` | other malformed user input |

## Acceptance gates

`0.1.0` is shippable only when all of these hold:

- legacy tests remain green;
- new provider, event-window, privacy, path, Git, classification, proposal, validation, demo,
  CLI, packaging, and offline tests are green;
- a clean install exposes `requirement-ledger` without runtime dependencies;
- the synthetic demo is deterministic apart from its output path and contains no personal
  data;
- the automated privacy canary blocks before creating the requested output;
- a single complaint never becomes confirmed `upstream`, and unavailable personal evidence
  never becomes confirmed `personal`;
- Git collection leaves HEAD, status digest, index, hooks, configuration, and working files
  unchanged;
- no command runs project code and no network/telemetry/external action exists;
- public docs do not describe legacy `--no-text` as share-safe;
- the wheel, sdist, changelog, CI, support/security/contribution files, Issue Forms, anonymous
  example, and handoff are present.
