# 需求确认单

一屏。字段固定。不写散文，不打太极，不加废话。它唯一的作用是**被反驳** ——
长到没人读，它就没法起作用。

模板见 [templates/confirmation-sheet.zh-CN.md](../templates/confirmation-sheet.zh-CN.md)。

## 必备字段

| 字段 | 装什么 | 什么时候算写坏了 |
|---|---|---|
| **目标** | 一句话：用户拿到什么，为什么值得做 | 只是把请求重述一遍，没点出结果 |
| **包含** | 逐条列出的交付物 | 条目是没有宾语的动词（「优化性能」） |
| **不包含** | 你刻意不做的那些 | 留空 —— 范围蔓延就是从这儿进来的 |
| **输入** | 真实文件、路径、样本、凭据、权限 | 写了一个磁盘上还不存在的文件 |
| **输出** | 产物和它们落在哪 | 只写「一份报告」，没有格式也没有路径 |
| **验收** | 用户拿来检查它的那个动作 | 写成形容词而不是动作 |
| **约束** | 截止时间、预算、平台、权限、不许碰 | 没说出口的限制在交付时才冒出来 |
| **执行位置** | 机器、系统、运行时、账号 | 默认就是你自己那台环境 |
| **未确认项** | 每个还没定的 `待确认`，以及谁欠这个答案 | 为了显得完工而清空 |

每一行都带自己的标签：`已确认`、`AI推断` 或 `待确认`。

## 标注规则

- `已确认` 需要一句你能指着看的用户原话。你自己那段漂亮的复述，在对方点头之前不算确认。
- `AI推断` 是真的下了决定，不是打太极 —— 写你选了什么，不是写「有得选」。
  「输出 CSV（`AI推断` —— 想要 xlsx 说一声就改）」对；「输出格式待定」不对。
- `待确认` 项要写清谁欠答案。没有归属的待确认项永远解决不了。
- 不要为了显得确定，把一条拆成两个标签。校验脚本会拦。
- 英文标签写大写，而且只有大写才算数。否则「run X, open Y, see Z」这样的验收动作
  会被读成一条 `OPEN` 项。中文标签没有这个歧义。

## 锁定

确认单只由以下两件事之一锁定：

1. 用户确认了 —— 整份确认，或逐条确认。
2. 用户明确授权：「这些细节你定」。此时所有 `待确认` 转为 `AI推断`，标签留着，继续可见。

沉默不算锁定。用户回复了消息里的另一部分也不算。如果你不确定它锁没锁，那就是没锁。

## 篇幅

确认单塞不进一屏，只有两种情况：任务对一份单子来说太大了 —— 拆开；或者单子在灌水。
九个字段，每个一到四行。不要前言，不要结尾总结。

## 机械预检

```bash
python3 scripts/check_confirmation_sheet.py path/to/sheet.md --lang zh
```

检查：九个字段齐全且非空、每条都有标签、没有一条挂两个标签、
两版之间没有 `AI推断` 被偷偷提级、`未确认项` 不是「正文里有待确认却在这里留白」、
以及总篇幅在一屏之内。退出 `0` 时打印 `VALID_SHEET`。

它只读形式。一份确认单可以通过全部检查，同时描述的是一个完全错误的项目 ——
那正是用户那句确认要解决的事。
